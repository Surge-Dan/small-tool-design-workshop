# 🛠️小工具设计工坊

### 面向小红书小工具的移动端设计与原型Skill

**把脑海里的小玩法，做成能点、能改、有自己样子的原型。**

</div>

一个人格测试、一张情绪卡片、一个晚餐推荐器……小工具设计工坊面向想验证玩法的创作者、产品经理和设计师，帮助你从想法出发，梳理用户怎么用、结果有什么价值，再生成可交互的移动端H5。

> 一个好原型，既要让人想点进去，也要让人知道点完能得到什么。

## 先从一句话开始

安装后，在新任务中直接说：

```text
使用$small-tool-design-workshop，做一个今天吃什么的小工具。
用户输入预算和人数，得到晚餐建议。
界面像菜市场的手写价签，生成离线可用的移动端单HTML。
```

只有一个模糊想法，也可以先聊玩法：

```text
我想做一个能分享的通勤穿搭小游戏。
先给我3个玩法方向和适合的人群，暂时不要写HTML。
```

已有原型时，可以接着改：

```text
只改结果页：把推荐理由讲清楚，增加返回修改按钮。
首页、配色和主流程保持不变。
```

## 适合做哪些小工具

| 类型 | 用户想完成什么 | 例子 |
| --- | --- | --- |
| 测试与测评 | 了解自己的某个特点 | 节日人格测试、生活偏好测试 |
| 生成与编辑 | 做出一份可以带走的内容 | 情绪卡片、文案生成器、分享图编辑器 |
| 计算与推荐 | 算清楚、少纠结 | 预算计算器、晚餐建议、通勤穿搭 |
| 轻量游戏 | 玩一下，得到反馈 | 抽签、选择挑战、互动小游戏 |

默认交付用于验证产品方向的原型，使用本地模拟数据。真实账号、支付、数据库、生产API和平台上传，需要另外明确需求。

## 从想法到原型，怎么走

1. **先定设计简报**：确认产品框架、页面布局、视觉方向和交付要求。信息不足时，给出1～2个具体方向供你选择。
2. **选择素材与工具**：按确认的目标选择图标、插画、字体和渲染方式，让素材与界面保持一致。
3. **搭好交互**：先走通入口、操作和结果，再按场景补齐输入错误、返回修改、重置和失败恢复。
4. **打磨视觉**：落实版式、材质、细节与反馈，默认按高保真可交互原型制作。
5. **检查再交付**：对照简报检查显示与操作，验证离线资源，说明哪些已验证、哪些是模拟、哪些还没测。

只给功能时，先定布局和视觉再开工；你已提供完整简报，或明确说“直接做，布局风格你来定”，就直接执行。已有决定不会反复确认。

你只要玩法，就交付玩法；你要可点击原型，就交付原型。局部修改沿用已确认的设计，不顺手把整个产品重做一遍。

## 🎨好看，要有来由

菜市场价签里的单位和价格，可以成为晚餐工具的信息骨架；穿搭工具可以用杂志拼贴组织服装关系；情绪记录可以像一页轻薄手册，让选择和书写自然发生。

主题会影响内容如何排列、用户如何操作、结果如何呈现。插画、贴纸、渐变和动效都可以使用，只要服务理解、情绪或辨识度，同时保证可读、可操作。

具体规则见[视觉语言](references/visual-language.md)和[AI风格反模式](references/anti-ai-slop.md)。

## 素材和渲染，也可以认真选

按目标使用统一的图标库、授权插画、特色字体或当前可用的生图工具。复杂动效可以借助GSAP，丰富的二维场景可以考虑Canvas／PixiJS，明确的三维效果可以考虑Three.js；具体方案跟着设计走。

制作过程可以联网获取资源、查文档或使用构建工具。离线交付时，所需素材和许可允许的依赖打包进HTML，保留必要来源与署名，打开文件即可使用。Skill会先检查工具是否可用；工具缺失时说明限制，影响确认效果的替代方案交给你选择。高成本生图、素材购买或长调研开始前先说明范围与成本。

详细选择与交付规则见[视觉资源与渲染工具](references/visual-resources.md)。

## 交互要经得起多点几下

根据任务检查相关情况：

- **输入不完整或不合法**：就近说明问题，修正后可以继续。
- **返回修改与重新生成**：保留输入，结果使用最新内容。
- **连续点击与清空重写**：状态不混乱，清空编辑内容前有确认或撤销机会。
- **无结果、保存失败或取消分享**：解释原因、保留内容，并提供适用的恢复方式。
- **窄屏与长内容**：文字不被截断，主要操作可见，导出内容完整。

有浏览器工具时实际打开检查；没有对应工具或设备时，如实标注未验证。检查范围跟着任务走，不给简单玩法增加一整套无关流程。

## 最后会拿到什么

- 一个HTML文件，内嵌CSS和JavaScript，可离线打开，无需构建工具或外部服务。
- 一段简短的设计说明：核心任务、操作路径和视觉依据。
- 已实现的需求与交互、实际验证结果、关键假设及限制。

默认移动端优先，以390×844为主要基准，同时关注窄屏显示。生成和保存等核心动作需要可操作；真机兼容与平台审核以对应验证结果为准。

## 安装

在Codex环境中，通过Skill安装器执行：

```powershell

  --repo Surge-Dan/small-tool-design-workshop `
  --path . `
  --name small-tool-design-workshop
```

安装后，在新任务中使用`$small-tool-design-workshop`，也可以直接描述需求，让Agent按任务匹配Skill。
