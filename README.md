# 🛠️小工具设计工坊

### 从一句想法，到能交给AI开发的小工具原型

**先说清楚要解决什么，再做好看、能点、能带走的原型。**

</div>

一个人格测试、一张情绪卡片、一个晚餐推荐器……小工具设计工坊面向想验证玩法的创作者、产品经理和设计师，帮助你从想法出发，梳理用户怎么用、结果有什么价值，再生成可交互的移动端H5。

> 一个好原型，既要让人想点进去，也要让人知道点完能得到什么。

## 已经有Agent，为什么还用它？

Agent本来就能写页面。这个Skill围绕视觉效果提供可复用的设计流程和交付工具，减少每次重新解释、看图猜规则和修改后丢失决定的问题：

- **需求有验收**：把“我想做一个工具”收敛成场景、输入、结果和可检查的例子；页面、状态与需求对应起来。
- **方向看得见**：需要时用参考图或关键页面小样选方向，确认后再做完整交互。
- **视觉有方法**：根据简报选择排版、物件、素材或空间路线，从关键画面扩展到完整状态；简约和复杂都按自己的质量标准打磨。
- **修改有依据**：沿用已经确认的设计，定位“不好看”或“没用”的具体原因，更新受影响的规则和证据。
- **交接有工具**：用标准库脚本导出HTML、设计记录、交接说明和已有截图，下一位AI不用只凭一张图猜功能。

这些能力不等于每次作品都更好。是否减少返工、是否比直接问Agent更符合需求，需要实际作品和对照测试验证；目前不宣称已证明优势。

## 先从一句话开始

安装后，在新任务中直接说：

```text
使用$small-tool-design-workshop，做一个今天吃什么的小工具。
用户输入预算和人数，得到晚餐建议。
界面像菜市场的手写价签，生成离线可用的移动端单HTML。
确认方案后再制作，最后导出可交给AI写代码的开发参考包。
```

只有一个模糊想法，也可以先聊玩法：

```text
我想做一个能分享的通勤穿搭小游戏。
先给我3个玩法方向和适合的人群，暂时不要写HTML。
```

已有原型时，可以接着改：

```text
只改结果页：把推荐理由讲清楚，增加返回修改按钮。
首页、配色和主流程保持不变。
```

## 适合做哪些小工具

| 类型 | 用户想完成什么 | 例子 |
| --- | --- | --- |
| 测试与测评 | 了解自己的某个特点 | 节日人格测试、生活偏好测试 |
| 生成与编辑 | 做出一份可以带走的内容 | 情绪卡片、文案生成器、分享图编辑器 |
| 计算与推荐 | 算清楚、少纠结 | 预算计算器、晚餐建议、通勤穿搭 |
| 轻量游戏 | 玩一下，得到反馈 | 抽签、选择挑战、互动小游戏 |

默认交付用于验证产品方向的原型，使用本地模拟数据。真实账号、支付、数据库、生产API和平台上传，需要另外明确需求。

## 从想法到原型，怎么走

1. **先定需求与验收**：确认用户场景、结果价值、输入规则、页面布局、视觉方向和交付要求。已有信息不重复问；信息不足时，给出具体方案和可检查的例子。
2. **看得见再选方向**：风格难以凭文字判断时，使用参考或关键页面小样；不默认制作两套完整原型。
3. **制作高保真原型**：选择合适素材，落实布局与细节，走通核心及相关异常交互。推荐要满足约束，解释要对应输入，不能只让字段齐全。
4. **检查再交付**：对照验收例子检查显示、操作和离线资源，说明哪些已验证、哪些是模拟、哪些还没测。需要交给AI开发时导出参考包。

只给功能时，先定布局和视觉再开工；你已提供完整简报，或明确说“直接做，布局风格你来定”，就直接执行。已有决定不会反复确认。

你只要玩法，就交付玩法；你要可点击原型，就交付原型。局部修改沿用已确认的设计，不顺手把整个产品重做一遍。

## 🎨好看，要有来由

菜市场价签里的单位和价格，可以成为晚餐工具的信息骨架；穿搭工具可以用杂志拼贴组织服装关系；情绪记录可以像一页轻薄手册，让选择和书写自然发生。

主题会影响内容如何排列、用户如何操作、结果如何呈现。插画、贴纸、渐变和动效都可以使用，只要服务理解、情绪或辨识度，同时保证可读、可操作。

具体规则见[视觉语言](references/visual-language.md)和[AI风格反模式](references/anti-ai-slop.md)。

## 一套SOP，多种表达

视觉流程有六个检查点：

```text
需求与视觉验收→表达路线→关键画面→完整状态→实际渲染与对抗复查→交付
```

它不要求六轮问答，也不规定所有页面长一样。完整简报或明确委托可以直接做；只改一个细节时，只检查相关部分。

| 路线 | 主要打磨什么 | 适合的表达 |
| --- | --- | --- |
| 版式与字体 | 字级、比例、网格、阅读节奏 | 极简计算器、复杂杂志排版 |
| 物件与材质 | 结构、触感、边缘、光影 | 复古掌机、纸张、仪表 |
| 图片与艺术指导 | 构图、裁切、素材关系、色板 | 摄影、拼贴、统一角色插画 |
| 空间与动态 | 层次、运动、材质、实际操作 | 二维场景、三维物件、复杂转场 |

路线可以组合，技术跟着目标选。简约不是粗糙，复杂不是堆库；渐变、玻璃、粒子和装饰都可以采用，检查的是表现依据和完成质量。

完成后从用户、艺术指导、怀疑者和下一位开发AI的立场复查。问题要指出具体画面或状态；主要缺陷修复后复查，不靠自评分证明“高级”。缺少渲染工具时标注静态检查，不能把代码无报错说成视觉通过。

完整流程见[视觉设计SOP](references/visual-sop.md)。

## 素材和渲染，也可以认真选

按目标使用统一的图标库、授权插画、特色字体或当前可用的生图工具。复杂动效可以借助GSAP，丰富的二维场景可以考虑Canvas／PixiJS，明确的三维效果可以考虑Three.js；具体方案跟着设计走。

制作过程可以联网获取资源、查文档或使用构建工具。离线交付时，所需素材和许可允许的依赖打包进HTML，保留必要来源与署名，打开文件即可使用。Skill会先检查工具是否可用；工具缺失时说明限制，影响确认效果的替代方案交给你选择。高成本生图、素材购买或长调研开始前先说明范围与成本。

详细选择与交付规则见[视觉资源与渲染工具](references/visual-resources.md)。

## 交互要经得起多点几下

根据任务检查相关情况：

- **输入不完整或不合法**：就近说明问题，修正后可以继续。
- **返回修改与重新生成**：保留输入，结果使用最新内容。
- **连续点击与清空重写**：状态不混乱，清空编辑内容前有确认或撤销机会。
- **无结果、保存失败或取消分享**：解释原因、保留内容，并提供适用的恢复方式。
- **窄屏与长内容**：文字不被截断，主要操作可见，导出内容完整。

有浏览器工具时实际打开检查；没有对应工具或设备时，如实标注未验证。检查范围跟着任务走，不给简单玩法增加一整套无关流程。

## 最后会拿到什么

- 一个HTML文件，内嵌CSS和JavaScript，可离线打开，无需构建工具或外部服务。
- 一段简短的设计说明：核心任务、操作路径和视觉依据。
- 已实现的需求与交互、实际验证结果、关键假设及限制。

默认移动端优先，以390×844为主要基准，同时关注窄屏显示。生成和保存等核心动作需要可操作；真机兼容与平台审核以对应验证结果为准。

## 📦把设计交给下一位AI

你可以直接说：“把当前原型导出成AI开发参考包。”无需先选前端框架，制作阶段也不接生产后台。

参考包包含：

```text
工具名-handoff.zip
└── 工具名-handoff/
    ├── prototype.html       可运行原型
    ├── design-spec.json     需求、页面状态、交互、规则和设计参数
    ├── HANDOFF.md           可读说明、验收、模拟部分和已知限制
    ├── AI-START.md          下一位AI的开工说明
    └── screenshots/         已有实际截图，按状态与视口记录
```

解压后把整个目录交给支持读取本地文件的AI；只接受附件的工具可上传它支持的文件，优先提供HTML、HANDOFF.md及关键截图。让AI先读AI-START.md，再按你的目标平台与技术栈实现。截图负责说明外观，设计记录负责说明行为，两者一起参考。

新版记录还可保留表现意图、关键视觉特征、制作方法和复查发现。未修复的阻断问题或未处理的主要问题不能标成复查完成；实际画面复查需有关联截图。打包器核验记录，不自动判断审美质量。

无截图工具时照实标注缺失。用户只要单HTML时不会强制输出整包，也不会给工具的终端用户增加“导出开发包”按钮。

打包器只依赖Python标准库，可重复使用：

```text
python scripts/build_handoff.py init --output <项目目录>/design-spec.json --title <工具名>
python scripts/build_handoff.py build --spec <项目目录>/design-spec.json --html <项目目录>/原型.html --output <新目录>/工具名-handoff
```

Skill负责填写实际设计记录，脚本检查确认状态、引用和证据文件并生成目录及ZIP。草稿、未解决的关键问题、缺失证据文件或无效引用会阻止导出；部分完成与未验证会明确标注。已有输出不覆盖。**打包成功不等于原型已经通过运行测试。**

详细格式见[AI开发交接](references/developer-handoff.md)，前置确认与修改方法见[需求和视觉评审](references/brief-and-review.md)。

## 安装

在Codex环境中，通过Skill安装器执行：

```powershell
python "$env:USERPROFILE\.codex\skills\.system\skill-installer\scripts\install-skill-from-github.py" `
  --repo Surge-Dan/small-tool-design-workshop `
  --path . `
  --name small-tool-design-workshop
```

安装后，在新任务中使用`$small-tool-design-workshop`，也可以直接描述需求，让Agent按任务匹配Skill。
