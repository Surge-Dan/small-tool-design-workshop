# 内部对照评估

修改Skill的关键流程后，用少量真实请求比较是否减少猜测、返工和设计漂移。评估用于内部改进，不建立公开案例集，也不成为每次制作原型的默认步骤。

## 三类任务

| 任务 | 观察重点 |
| --- | --- |
| 模糊想法 | 问题是否帮助决策，是否展示具体布局与视觉取舍，确认次数与无效追问 |
| 完整需求 | 能否直接制作，需求覆盖、画面与状态一致、操作成本、运行与离线边界 |
| 局部修改 | 改动是否完成，已认可部分是否保住，能否恢复，证据是否仍对应当前版本 |

每类分别给普通Agent与使用Skill的Agent相同请求、原始资料、工具权限、交付要求和相近时间预算。两组不互看产物，不给评估者预设问题或期望答案；参考、素材和费用权限一致。模糊任务使用相同的预先准备用户回答，记录适应对话的差异；两组确认方向后再制作，不拿方向建议与完整原型比较。

实际产物放在仓库外的临时目录。局部修改先冻结同一个初始HTML再交给两组；不能各自修改不同作品。完整需求使用真实内容，记录核心操作、错误与返回状态；用对应浏览器或设备检查，缺工具的项目标为未测。

## 记录实际结果

每次记录任务原文、Skill提交、Agent／模型、工具与时间预算、确认轮次、产物路径及哈希、已执行操作与证据、需求遗漏、实际返工和未验证项。时间由工具或日志测量，无法取得时留空，不能估算成实测。

用户偏好通过匿名展示相同内容与视口的实际产物收集，支持偏好A、偏好B、无差异，并记录原因。尚未收集时留空；设计者自评分或另一个Agent的评价不能代替用户偏好，也不能证明别人会复用。

样本覆盖简约排版、资产/材质表达、复杂编辑或动态中的不同任务，不固定某类风格为优秀。分别记录对象与操作结构是否贴合、参考是否真正影响决定、关键资产是否完成、确认画面与成品是否偏离；视觉、行为、动态、显示各自留下证据。记录核心任务的点击/滚动、方向误解和实际返工，只报告实测，不设虚构转化目标。

模糊任务观察用户能否通过关键画面或局部操作作决定；完整需求观察是否直接推进；局部修改观察是否仅检查受影响项。没有必要的小样、重复确认和素材调用同样算成本。规则提示词命中不等于执行成功；画面对照工具不提供审美评分。

区分以下结论：

- 提示词覆盖：`evals.json`记录预期行为，不代表已完成生成。
- 结构与机制：单元测试核验打包、版本失效与恢复，不代表原型效果好。
- 行为与视觉：实际产物、操作日志、截图与对照差异；仅能说明对应任务与环境。
- 用户价值：真实选择、返工与再次使用反馈；没有这些数据，不宣称已证明优势。

一次先做三类的小规模对照，发现具体失败后只改相关规则。需要付费素材、生图、大批量运行或长调研时先说明范围与成本。评估报告保留未测项和差异，不能因为使用了Skill就预设它更好。
