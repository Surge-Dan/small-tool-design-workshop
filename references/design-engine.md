# 从任务到设计概念

需要推导结构或原创方向时读取。需求确认由[需求与评审](brief-and-review.md)负责；这里解决为什么这样组织和表现，不重复访谈。

## 找到值得操作的对象

先写清：用户面对的对象、核心动作、可用结果、最费力的环节。图片、记录、候选方案、路径和游戏物件适合不同结构；不要先决定Hero、表单与结果卡，再把主题填进去。

路径写成`对象初始状态 → 用户动作 → 可见变化 → 下一步用途`。用真实输入走通一个片段；价值可以是省力、创作、理解或娱乐，不为娱乐工具硬编效率指标。

明确需求对应页面、行为和验收。按任务补返回、重复、取消和错误；状态可在原页发生，不因流程完整增加页面。操作骨架按需见[experience-archetypes.md](experience-archetypes.md)。

## 找参考，而不是找外壳

优先看用户参考，再按缺口少量查找。业务来源解释规则，视觉参考解释表现，技术文档解释实现；不能用业务文章证明字体和配色。

实际看过后记录`来源 → 观察 → 本次采用的决定 → 不迁移的部分 → 未知项`。链接、风格词、搜索摘要不算已查看画面。截图不能证明动画、技术栈、触控和导出；热度不是设计质量评分；平台状态栏与分享壳不默认复制。

可跨领域借鉴相似操作问题：比较、选中、编辑、揭晓、导航或反馈。借关系、密度、材质与节奏，不复制品牌、人物或整套页面。原创方向标明依据，不编造来源。

## 发散操作与表现，不只换色

结构未定且确有取舍时，内部比较少量概念：对象怎么排列、动作在哪里发生、结果怎么变化、视觉由什么承担。淘汰同一表单的配色变体；不为原创重造熟悉控件，也不把每个工具变成掌机、纸张或拼贴。

| 决定 | 判断依据 |
| --- | --- |
| 结构 | 当前对象、主操作、比较/编辑关系、连续操作成本 |
| 表现 | 内容身份、用户偏好、实际参考、字形和资产能力 |
| 反馈 | 什么改变了，能否继续或撤回 |
| 实现 | 关键效果、环境、资源、离线和导出条件 |

用户选的是体验，例如就地编辑与分步配置。用具体内容解释取舍并推荐，不让用户先学设计术语。已有确认结构或明确委托时沿用范围，不重新发散整个产品。

## 验证最有特点的片段

做有代表性的关键画面；交互不确定时加一次核心动作和结果。主题进入对象关系、控件或反馈，不只停留在标题。片段同时校准信息主次、素材精度与可行性，不先做装饰欢迎页。

仅授权方向探索时，只做范围明确的小样或局部交互；确认后扩展。完整需求或明确委托直接做时，内部验证片段。方法见[视觉制作](visual-sop.md)。

## 内容和文案一起设计

先判断什么能由缩略图、字形样本、选中态、空间位置或变化直接表达，再写剩余说明。复杂配置可以详细，但按当前任务展开；不以固定字数牺牲理解。

动作直接命名；错误说明问题与恢复方法；结果有可理解的依据。移除重复双语、伪状态和内部设计标签。保留有价值的情绪与品牌表达，不用空泛口号填空。

决定留在同一份简报或`visual.design_plan`：对象、核心动作、结构理由、参考迁移、保留特征、资源与渲染选择。参数以实际画面为准，记录不证明设计质量。
