# 体验骨架速查

只在需要判断玩法、结果结构或页面状态时读取。体验类型是任务骨架，不是视觉模板。

| 类型 | 用户期待 | 最短路径 | 结果必须回答 | 常见问题 |
|---|---|---|---|---|
| 测试测评 | 我是什么 | 选择 → 累积 → 揭晓 | 结论、依据、下一步 | 只有标签，没有解释 |
| 分析诊断 | 我为什么这样 | 输入 → 分析 → 解释 | 关键发现、可信边界、建议 | 把推测说成事实 |
| 生成器 | 给我一个成品 | 设定 → 生成 → 预览 | 产物、修改、保存/分享 | 生成过程比产物更复杂 |
| 计算工具 | 算清楚一个数 | 输入 → 反馈 → 调整 | 数值、单位、计算口径 | 结果没有上下文 |
| 推荐工具 | 帮我缩小选择 | 描述 → 筛选 → 推荐 | 推荐理由、继续探索 | 先问太多问题 |
| 内容编辑器 | 我想做一张东西 | 选模板 → 编辑 → 预览 | 成品预览、修改、导出 | 模板先于用户任务 |
| 游戏化工具 | 我想玩一下 | 懂规则 → 操作 → 反馈 | 当前状态、结束条件、结果 | 装饰和规则混在一起 |

## 轻量记录类的优先结构

当用户只是选择今天的情绪、写一句话、生成一张卡片时，可优先使用一页结构：

```text
日期 / 页面身份
标题
一个核心选择
一块可选记录区
一个生成或保存动作
```

不要拆成欢迎页、说明页、选择页、记录页四步。额外步骤只有在规则或输入确实复杂时才成立。

若需求包含历史浏览、多条管理、复杂编辑或特定分页，按实际任务组织，不能用这个例子替代用户的流程和视觉要求。

## 按场景选择状态

对适用状态明确触发、反馈、保留的数据和下一步，不要求每种状态都有独立页面：

- 初始：用户能立即看到核心动作；
- 未完成：明确提示缺少什么；
- 结果：结论、依据或内容价值可见；
- 返回：修改后重新生成；
- 重来：清空本次输入，但不要悄悄丢失用户仍在编辑的内容。
- 输入边界：必填为空、非法数值、范围上下限和长文本按实际字段处理，错误靠近字段，修正后可继续；
- 无结果或规则限制：说明原因，允许调整相关输入，不编造匹配项；
- 重复操作：生成、提交和保存保持状态一致；存在异步任务时避免重复提交和旧结果覆盖新结果；
- 保存/分享：成功反馈有依据，失败提供可行替代，用户取消不报错、不清空内容。

处理态只在等待真实或模拟计算时需要。若生成是本地瞬间完成，不要伪造长 loading。
