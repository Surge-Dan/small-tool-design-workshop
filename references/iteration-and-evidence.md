# 修改保护与证据版本

局部修改、恢复旧版或导出开发参考时读取。目标是保住用户已认可的部分，并识别与当前原型不对应的证据。快照和哈希不判断审美，也不能证明未指定区域没有变化。

## 修改前后

1. 读取当前HTML与已有记录，把本次范围缩成“改动／保留／验收”三个短项。没提供记录时从当前作品提取，不重新采访整个产品。
2. 保存可恢复快照，再修改。单HTML快照只需HTML；有设计记录时同时保存JSON和它引用的附件。方向讨论、小样首次创建无需先保存不存在的原型。
3. 修改后走受影响路径，复查保留的布局、素材、操作与数据规则。字节差异只能定位改动，需用实际画面与操作判断保留项是否成立。
4. 更新相关需求、规则与设计参数，移除过期证据及引用，降低失效的验证级别。无复查依据时不保留“已验证”结论。

## 保存与恢复

这些命令由Agent执行，用户只需说明改哪里或要恢复。脚本只依赖Python标准库；用户项目放在自己的项目目录，避免写入Skill安装目录。

```text
python scripts/prototype_state.py snapshot --html <项目>/原型.html --spec <项目>/design-spec.json --output <项目>/.history/修改前
python scripts/prototype_state.py restore --snapshot <项目>/.history/修改前 --output <项目>/恢复版本
```

没有JSON时省略`--spec`。快照保存原型、设计记录及引用附件的字节与哈希；缺文件或越界路径会拒绝。恢复先核验快照，写到全新的目录，保留当前作品；之后按用户选择把恢复版本作为工作版本。快照只覆盖离线单HTML及设计记录引用的附件，不备份浏览器存储、外部服务、未引用素材或多文件应用依赖。

快照不进入默认交付包，不新增终端用户界面的“开发版本”按钮。Python不可用时手动复制同一范围到新目录，说明未执行脚本。

## 证据绑定

新记录使用可选`prototype_sha256`标识实际HTML字节。完成真实检查后，明确指定刚观察过的证据ID；有附件时同时记录`attachment_sha256`：

```text
python scripts/prototype_state.py bind --spec <项目>/design-spec.json --html <项目>/原型.html
python scripts/prototype_state.py bind --spec <项目>/design-spec.json --html <项目>/原型.html --evidence-id E1 --evidence-id E2
```

第一条只绑定设计记录，不改任何证据。第二条只标记明确指定的证据；命令本身不打开浏览器、不截图、不执行测试。只能标记本次确实观察过的记录，不能批量给历史截图盖新哈希。

已绑定的新记录要求包内每条证据也绑定版本，有附件时还需绑定附件哈希；仅运行第一条不会让旧证据通过。尚未观察的条目应移除并同步引用及验证级别，不要为了导出批量绑定。

HTML字节变化后，原绑定失效。先检查受影响内容，删除或替换旧证据及引用，再绑定当前记录和新观察。文本或换行变化也会改变哈希；脚本保守检查字节版本，不推断变化是否影响语义。只复查本次相关路径，未经重查的旧结论可留在快照中，不能作为当前版本验证。

导出会拒绝已绑定但与当前HTML不匹配的设计记录或证据，以及内容变化的已绑定附件。未绑定的旧记录仍可导出，交接说明明确版本无法核验；不会自动把它们改写成新证据。

开发包中的`ARTIFACT.json`记录实际导出HTML及附件哈希、哪些证据绑定了版本。它用于发现文件漂移，不证明日志真实、需求完整、动画流畅或视觉合格。
