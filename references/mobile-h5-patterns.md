# 移动端 H5 核心模式

只在生成或修改移动端单 HTML 原型时读取。它是设计底线，不是要求每次跑完整审计。

## 页面和触控

- 主要基准 390×844，同时关注 320、375、414 宽度；
- 可点击区域尽量不小于 44×44px；
- 关键按钮要在首屏或核心内容之后自然可见；
- 不依赖 hover、右键或精细拖拽；
- 处理安全区、软键盘遮挡和长文案换行。

## 输入和选择

- 选择项要显示选中态、未选中态和错误提示；
- 错误靠近对应输入，不用模糊的全局 toast；
- 可选字段明确写“可选”，不要让用户猜；
- 输入内容在返回修改后保留，点击“重来”才清空；
- 字数限制应在用户输入时可见，但不抢夺页面主层级。
- 数值输入按任务校验单位、范围及整数/小数规则；长文本、全空格和边界值不能让结果溢出或显示无效值；
- 修改后重新生成必须使用最新输入，旧结果不能误呈现为当前结果；
- 重置会丢失用户编辑内容时给确认或撤销机会，重复点击不能造成状态混乱。

## 结果和分享

- 结果页至少展示结果名称、解释或依据、下一步动作；
- 分享卡要保证文字足够大、内容可读、主题色有对比度；
- 保存/分享失败时提供下载或复制等本地替代；
- 用户取消分享时保留结果，不显示失败；替代方式应与产物匹配，无法导出图片时不能把“复制文字”称为已保存图片；
- 成功文案必须对应实际证据：触发浏览器下载只能提示“已发起下载”，不能断言已写入相册或下载目录；
- 导出内容与预览保持语义和主要视觉一致，检查长文本、换行、日期和边缘元素，不能只确认下载按钮有事件；
- 不把“能在浏览器下载”描述成“已通过平台审核”。

## 单 HTML 约束

- HTML、CSS、JavaScript 默认内嵌；
- 不使用构建工具、CDN、远程字体、外链图片或网络 API；
- 模拟数据和计算/推荐规则可解释、可复现；用户指定的随机玩法保留随机性，测试时可使用固定种子；
- 若用户没有要求，避免 Worker、WASM、iframe、登录、支付和真实上传。

## 轻量交付检查

1. 核对明确需求与实现，检查排除项和局部修改范围；
2. 有浏览器工具时实际打开文件，走一遍核心路径及本任务适用的输入错误、返回修改、重置、无结果和保存/分享恢复路径，检查控制台错误；
3. 在 390×844 及 320px 窄屏查看首屏、长内容、结果和关键状态，检查阅读、触控区域、焦点和溢出；涉及导出时查看生成文件是否完整、与预览一致；
4. 检查无意外外部依赖；阻断任务、丢失数据、结果不可读的问题修复后复查相关路径。

在桌面浏览器改宽度不等于真机验证。软键盘、系统分享、相册保存等没有对应设备证据时标明未验证；缺少浏览器工具时只能报告静态检查。交付简述实际操作及结果，不把未执行的检查写成通过。用户要求平台上传、真机兼容或完整审计时，才扩大验证范围。
