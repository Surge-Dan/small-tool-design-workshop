# 动画与交互：让状态变化可理解、连贯且可中断

涉及连续操作、布局变化、页面转场、手势或场景运动时读取。静态方向建议无需填写运动表；已有局部改动只检查受影响行为，不强制增加动画或安装库。

## 从对象关系开始

结构阶段确定：用户操作什么、状态变为什么、哪个对象需要保持身份和位置、用户接下来做什么。颜色变化、移动、形变、遮挡和节奏根据这些关系选择，也可以服务确认的品牌与情绪。

按实际任务分配运动职责：

| 职责 | 要解决什么 | 设计重点 |
| --- | --- | --- |
| 微反馈 | 让用户知道按下、选中、完成或输入错误 | 反馈及时、状态清楚、不抢注意力 |
| 状态衔接 | 新增项、重排、展开、数字变化仍有可理解关系 | 对象连续、布局稳定、焦点和位置保留 |
| 页面转场 | 用户知道来自哪里、去了哪里、如何返回 | 来源与目标关系、进出节奏、返回位置 |
| 表现性运动 | 揭示、游戏或空间物件具有节奏与性格 | 内容主次、实际运动、可跳过或中断行为 |

轻量记录不必拥有四类运动；可即时完成的计算不伪造加载。用户明确的动态效果是需求，不因“只是原型”静默删除。

## 关键运动规格

先在内部简报写清下列内容；需要交接时可用`visual.motion_plan`保存关键项，不为每个按钮建立长文档：

```text
触发与前后状态 → 表现目的 → 保持的对象关系 → 变化属性
→ 时长/曲线 → 快速重复和中断行为 → 减少动效回退 → 验证范围
```

微反馈约100–180ms、状态衔接约180–320ms可作为调试起点，展示性运动按表达与任务决定。它们是起点，不是统一规范；入场与退场、行程长短、触控与指针应分别判断。曲线需与受力和速度感一致，不统一弹簧，也不在所有变化上加延迟。

## 让状态与运动协同

- 业务状态有明确的提交时刻，不依赖`animationend`才保存或结束；跳过、取消与减少动效不会丢失结果。
- 重复点击按任务处理：立即切换、重定向、取消或暂禁操作，并明确反馈；有异步任务时避免旧结果覆盖新结果。
- 连续输入和同一对象变化优先保留DOM节点、选区、焦点和滚动锚点。不要为了改变一个完成态就无差别重建可编辑区域；确需重建时显式恢复这些状态。
- 新增或删除一项的空间变化要让用户理解去向，必要时做布局过渡；旧项退出、剩余项移动与新项出现的节奏有主次。
- 弹层、页面和场景处理进出两端：焦点进入与返回、背景操作隔离、退出时取消或收束运动。高频任务的动画不阻塞下一项输入。
- 手势与滚动协调，提供按钮或键盘替代；错误恢复无需完成复杂手势。触觉反馈仅在真实支持且有必要时使用，不把视觉晃动称为设备振动。
- 持续场景重进时不重复创建循环；离开或隐藏时按需暂停，释放临时监听与资源。
- `prefers-reduced-motion`下移除大位移、弹簧、闪烁及非必要持续运动，保留清晰状态；可保留必要的短淡入或直接切换，业务结果一致。

## 按行为选择实现

简单按压与稳定节点的状态反馈可用CSS；需取消、重定向或动态参数时考虑Web Animations；同一对象跨位置变化可用布局过渡/FLIP；复杂编排才考虑时间轴库。Canvas/WebGL用于确认的场景表现，保持可访问的操作与降级。

CSS声明了transition不等于实际发生过渡：同一次重绘直接插入最终状态，可能没有前后状态可供插值。应在实际操作中观察，不凭源码推定动画自然。外部库、字体、模型及离线打包按[visual-resources.md](visual-resources.md)执行。

## 动态验收与停止

在目标环境实际检查：操作前、运动中、结束后；快速重复；中途返回或关闭；返回后的焦点/滚动；减少动效；持续场景重进。检查状态没有串跳、操作没有被吞、内容可读、结果与输入一致。按任务选择有关项，不对没有场景循环的简单表单运行场景压力测试。

需判断流畅度时按实际环境观察掉帧和响应，能测量才记录时延或帧率；不设未经设备验证的统一60fps保证。必要时记录短视频、关键时间点截图与操作日志；静态画面不能证明运动，桌面浏览器模拟也不等于手机触觉、软键盘或真机性能已测。

修复已知阻断与主要动态缺陷后只复查相关路径。与确认方向一致、核心及相关恢复操作可用、动态关系连贯且可中断后交付；未验证范围如实标注，不无限微调曲线。
