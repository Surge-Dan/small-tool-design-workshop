# 从参考到可实现的视觉语言

用于创建新视觉方向、重定视觉，或将认可小样落实为原型。局部修字、已有规则内加状态不重跑；这是内部设计推导，不是更多访谈或新增审批。详细研究来源不随正常任务加载。

## 1. 先判画面的角色

| 当前画面的成功标准 | 优先组织 | 不要误套 |
| --- | --- | --- |
| 操作：完成选择、计算、编辑、记录 | 当前对象、直接反馈、连续操作、修改与恢复 | 海报式标题、展示壳、装饰挤占操作 |
| 阅读：理解结果或依据 | 结论、层次、比较关系、真实长内容 | 全页按钮与重复卡片抢占阅读 |
| 体验：探索、玩耍、揭晓、创作 | 对象与动作、空间关系、情绪与节奏 | 为极简删掉玩法的主要表现 |
| 传播：使用或分享一张独立产物 | 单张构图、清晰焦点、可读文字、裁切边界 | 把按钮、导航和编辑工具一起画进结果图 |

角色按画面而非产品名称决定，可混合但主次明确。操作页可以有辨识度，传播产物也可以克制；不因“小红书”自动加口号、贴纸、封面式标题或引导分享。画布尺寸按实际交付要求确定，不用图文卡片的比例限定交互页面。

## 2. 带着缺口看参考

用户上传图片时先按[图片风格迁移](image-style-transfer.md)判断参考类型、可见范围与还原意图；没有偏好时按[风格发现](style-library.md)提出具体推荐。图库不替代实际观察，也不要求新增访谈。

优先用户已经给的画面或本项目认可画面。需要外部参考时，先小量获取足以回答问题的材料；不知道为什么继续找，就停止。没有图像访问能力时，不把搜索摘要当成看过画面。

- **结构参考**：相似动作的真实产品。看信息重心、密度、列表／编辑关系、控件与导航，不限定同一题材。
- **艺术参考**：有用的字形、印刷、摄影、插画、材质或构图。看它如何组织视觉，不只记风格名称。
- **状态参考**：仅在关键行为不确定时补看选中、编辑、空态、返回、键盘等。静图不能证明动态。

这些是参考职责，不是强制三张图。一个来源可回答多个问题；一次只解决字体或构图的缺口也可以。付费素材库、MCP、账号和新Skill都不是必需依赖，不擅自安装、购买或调用批量生成。

对关键观察留下短链：`看到了什么 → 为什么适合本任务 → 具体采用什么 → 哪些不能照搬`。例如窄数量列支持逐行核对，而手机样机外框仅用于展示；前者可能进入原型，后者通常不进入。移除来源商标、水印与平台壳，不借复制现成品牌代替设计。

## 3. 把风格拆成可执行的语法

在同一份简报或已有设计记录里写一份短的视觉契约，按任务取必要项，不另造长文档：

| 规则 | 应说明什么 |
| --- | --- |
| 构图与密度 | 第一眼的对象、对齐轴、主要区域比例、行宽、连续内容的疏密；首屏真实能放多少内容 |
| 字形与层级 | 真实中文字体或回退、标题／正文／数字的角色、字重和断行；不是只写“高级黑体” |
| 色彩与表面 | 背景、正文、动作、完成和警示的职责；纹理的强度、边界及不应干扰的区域 |
| 形状与控件 | 按钮、选项、纸张、弹层分别怎样收边；一致的轮廓逻辑，不是所有对象相同圆角 |
| 资产与辨识 | 图像主体、比例、裁切、描边／光源，以及哪个特征承担记忆点；不需要图就不补占位插画 |
| 行为与变化 | 一次核心动作前后改变什么、动作出口在哪里、继续操作保留什么；高频反馈不抢视线 |

把关键角色落成少量实际参数，放入已有`visual.tokens`与设计决定中；不要复制上个项目的数值。共同规则固定，页面构图按任务变化；如需偏离，说明内容或操作理由，避免“全套一致”变成复制页面。

结构、表现方式、配色可独立选择，但需检查组合：高密度操作未必适合大面积插画；粗颗粒材质不应铺在小字下面；多色表达不能混淆状态。遵从用户已明确的审美，不强制单强调色、衬线标题、系统黑体或固定装饰数量。

## 4. 为有辨识度的部分分配制作精力

根据任务选择主要的表现重心：可以是字形与数字排版、独特操作对象、精细图像，或状态反馈，不要求每页有Hero。其他元素衬托它，不同时争抢注意。

做一次内部反事实检查：去掉标题和装饰纹理后，是否还保留有意识的内容关系、比例和操作？如果没有，说明主题只是一层皮肤；修结构或表现，不继续加装饰。这个检查不否定用户指定的物件主题，也不要求每个工具发明新交互。

主资产先完成一个代表性样本，按最终手机显示尺度检查，再扩展同一制作语言。后续图像可引用认可图作为锚点，保持线条、光源、色板和材质；需要不同角色时，主体轮廓与姿态必须有区别。品牌统一不等于角色换色。图片里的中文不清晰时，用真实文本排版或修复，不把错误字形带进原型。

## 5. 选择最省返工的关键片段

- **代码优先**：列表、表单、计算与编辑等，先用真实中文、真实控件做一个高保真HTML片段，减少图片到代码的二次转译。
- **图像优先**：图像、场景或材质决定效果时，可先出关键视觉再实现；生成前遵守成本授权。静态小样不证明功能成立。
- **已确认方向或明确委托**：片段可作为内部制作步骤，不重复要用户确认。只有看不懂的方向或实质取舍才展示并询问，合并短简报和关键画面，不连续问“是否继续”。

不默认生成多屏、手机外壳、插画或三套方案。只扩展本次需求真正需要的画面与状态。

## 6. 从小样到代码，保留视觉而非关键词

用认可画面或内部关键片段作为对照依据，先统一内容、状态、视口和滚动位置；有手机外框时只比较内容区域。参考只覆盖某一状态时，其他状态按同一视觉契约推导，不假装全部获批。

先对照轮廓与关系：区域位置／占比、对齐、主次、密度；再看字体实际渲染、行距、资产清晰度、裁切、圆角和材质强度。数量变多、中文变长或出现键盘时，允许按已确认规则适配，不机械锁死坐标。技术限制导致明显降级时说明可达选择，不静默用粗糙占位替代。

将真实UI元素用于输入、选择、阅读与反馈；图像只承载适合图像的部分。不能整页图片加透明热区冒充完成的原型。需要分享图时单独检查产物，不把操作页和传播图混为一体。

首次实际渲染集中找最影响质量的问题，按原因合并修正，再看受影响画面；没有具体缺陷就停止。功能检查不证明视觉好，小样好看也不证明代码还原好。更多检查按[视觉SOP](visual-sop.md)按需执行，不追加默认长审计。
