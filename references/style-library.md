# 风格发现与路由

仅在风格未定、用户不知如何表达或明确要探索时读取。这里是可执行的设计起点，不是24套布局模板，也不宣称穷尽所有审美。已有视觉契约优先；新方向可库外原创，不为匹配名称改掉用户的明确要求。

## 先推荐，而不是出问卷

从已知任务推导：使用时刻 → 高频动作 → 信息密度 → 希望得到的感受 → 可用素材／实现约束。把感受当待验证假设，不把“年轻女性”“小红书”“记账”自动映射成粉色、贴纸或纸张。

信息够用就推荐；缺口真影响选择时，只问一个日常问题，例如“你希望打开就一眼核对完，还是愿意慢慢翻看？”不要连续问色板、字体、设计流派。用户明确委托时自行选择并说明，不新增审批。

默认提出一个推荐。存在明显不同的使用取舍时，最多先加一个备选：

> 我建议做成随手勾选的小账本：打开就是物品，数量靠右，装好后条目变淡，完成前仍能复查。它适合收拾时快速核对。另一个方向是物品插画，辨认更直观，但同屏能放的项目更少。

这是表达方式示例，不是行李工具的默认答案。每次建议用真实内容说明：**第一眼的对象／操作如何发生／可见特征／适配理由／主要取舍**。不靠“高级、治愈、有质感”兜底。不是所有对比都要生图：列表用真实HTML片段，依赖画风的方向才考虑图像小样；成本沿用已有约定。

用户回应“差不多”时，结合上下文判断认可范围，不强行追问所有细节。说“都不对”时问最不喜欢的具体部分，保留已确认任务，不继续无方向抽卡。

先看本索引，挑最可能的一两个方向，再读对应家族文件；不要默认读取四份细则。无论选哪种风格，页面结构仍由任务决定。

原来的六种样例只是探索结果，对应其中部分方向；不是六个生产路线。`typographic / object-led / asset-led / scene-led`仍是制作重心，不能与风格编号互相替代。

## 组合不是拼盘

先选一个主语法，再按明确理由借一个局部特征。例如原生清单借纸本的细分隔，不是叠加纸纹、像素字、玻璃按钮和3D物件。只共享有用规则：状态色、字体角色、轮廓或光源；操作页与分享页可以不同构图。主语法不必属于本库，用户参考可成为独立来源。

把方向压缩为短契约：`对象与重心｜构图与密度｜真实中文层级｜色彩职责｜控件轮廓｜资产与行为`。从内容、选择前后状态、长文案和手机显示尺度检查它，不给库内风格盖“必定好看”的章。
