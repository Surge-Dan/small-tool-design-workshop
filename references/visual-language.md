# 视觉语言：让界面像它所服务的内容

只在需要定视觉方向、排版或高保真原型时读取。

缺少已确认的布局/视觉简报、也未获直接执行授权时，先提出具体方向并确认。产品功能清楚不等于已确认视觉；用户的明确参考和局部修改要求优先。

## 视觉选择顺序

1. 先确定产品的物件、动作和使用场景；
2. 再选择界面材料和版式；
3. 最后选择颜色、字体和动效。

不要从“高级、治愈、科技、简约”开始。它们没有足够的设计约束。

尊重用户给定的风格和参考，从具体内容决定信息层级、组件形态和结果表达。熟悉的交互控件可以复用，主题辨识度不必靠每次发明新的布局；也不能把所有主题统一成纸张手册。信息密集、编辑器和游戏应有各自适合的结构。

## 版式优先级

- 首屏先放用户要理解或操作的内容；
- 标题承担命名，不承担空泛宣言；
- 辅助文字只解释规则、状态或下一步；
- 空间感来自真实的留白和对齐，不来自大块空白加一句口号；
- 组件按内容关系分组，不按“卡片看起来漂亮”分组。

## 笔记本/手册类界面

把纸张当成信息结构：

- 日期、页边、横线、装订线、批注可以表达页面身份和记录关系；
- 标题、选项、记录区、行动按钮应像同一页里的不同书写层级；
- 选择项适合使用行、方框、短标签，不要自动变成五张圆角卡片；
- 结果卡应像从页面中自然长出来的另一页，而不是突然切换成通用渐变卡。

这是笔记本主题的参考，不是所有轻量工具的默认皮肤。纹理、印章、贴纸和插画可以服务情绪、品牌和辨识度，但不能压过内容、削弱对比或挡住操作；只有没有依据或干扰体验时才删除。

## 色彩和字体

- 颜色优先表达状态、主题或层级；
- 同一页面通常只需要一个强调色，结果变化时再使用主题色；
- 中文标题可用有性格的宋体/明朝体，正文使用清晰的系统黑体；
- 不为“设计感”强行加入英文、数字编号或伪栏目名；
- 字号、行高和对比度优先保证移动端阅读。

展示级原型按内容选择有辨识度且清晰的字体；可以采用许可允许的外部字体，但离线版本须内嵌所需字形并提供回退。图标保持同一家族或一致的线条、尺寸和光学重量，插画保持统一的形状、色板、描边和材质。资源选择按需参考 [visual-resources.md](visual-resources.md)。

## 动效

优先建立一致的动效节奏：翻页、揭示、生成或状态变化按任务需要选用，不强制数量。动效可服务反馈和情绪，但不能阻断操作、伪造等待或掩盖结果。尊重 `prefers-reduced-motion`。

## 移动端底线

以 390×844 为主要基准；主要操作可触达、可见、可读；不依赖悬停；键盘焦点可见；内容在 320～414 宽度下不溢出。详细模式见 `mobile-h5-patterns.md`。

有浏览器工具时检查实际渲染的首屏层级、长内容、选中/错误状态、结果与导出图；发现裁切、拥挤或不一致时修正。缺少工具时明确视觉仅做静态检查，不凭 CSS 推断已通过显示验收。

以确认的视觉方向为验收依据，检查字级、行距、对齐、留白节奏、插画清晰度及边缘、材质/光影的一致性，以及动效是否自然。素材加载失败、字体替换或渲染降级时核心内容仍应可读可操作，并如实说明与目标效果的差距。
