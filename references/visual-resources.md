# 视觉资源与渲染工具选择

在高保真任务需要图标、插画、图片、字体、复杂动效或外部能力时读取。目标是实现确认的设计效果；不要求每个原型接 API、安装库或调用生图。

由 [visual-sop.md](visual-sop.md) 先确定表现意图，再用这里选择具体资源；技术复杂度不代表视觉质量。简约版式也可用精细字体，复杂排版未必需要三维，明确材质／空间目标也不因“只是原型”而自动简化。

## 从目标效果选择方案

| 需要的效果 | 可选方案 | 选择依据 |
| --- | --- | --- |
| 精细布局、价签、轻反馈 | HTML/CSS、内联 SVG | 排版和少量矢量元素足够表达主题时直接制作 |
| 统一图标 | Phosphor、Tabler 等图标库 | 根据确认风格选择一个家族，取实际需要的 SVG，统一线条和大小 |
| 角色、摄影、纹理或主题插画 | 用户素材、授权素材库、可用生图工具 | 先看已有素材能否满足风格，决定构图、色板和用途后获取或生成 |
| 字体特色 | 系统字体或许可允许的外部字体 | 检查中文覆盖、可读性和内嵌/子集化许可，准备回退 |
| 状态反馈、可中断运动与复杂转场 | CSS、Web Animations、布局过渡／FLIP、GSAP | 稳定节点的轻反馈用CSS，取消/重定向按需用Web Animations，复杂编排再考虑时间轴库 |
| 丰富的二维场景、粒子或游戏 | Canvas、PixiJS | 场景数量和动态效果确有需要时使用，保留可访问的 DOM 控件 |
| 明确的三维物件、光影与材质 | WebGL、Three.js | 用户确认三维方向后选择，准备低性能/不支持 WebGL 的可用回退 |

库名是候选项，不代表当前环境已安装、已联网或已获得使用权。按实际版本查官方文档与许可，不猜 API 和许可证。官方入口：[Phosphor](https://phosphoricons.com/)、[Tabler](https://tabler.io/icons)、[GSAP](https://gsap.com/docs/v3/)、[PixiJS](https://pixijs.com/)、[Three.js](https://threejs.org/)。

## 资源获取与外部能力调用

1. 先对照已确认简报，写清需要的素材及其在页面中的角色；可直接使用已授权素材，无须重复确认。
2. 检查当前环境可用的工具、技能、已连接服务和本地资源。可用时利用 frontend-design 等设计技能、imagegen 等生图能力或浏览器/连接器获取资源；这些名称仅是有条件的路由提示，不构成不存在工具时的依赖。
3. 需要外部 API 时先读实际接口或工具 schema，核对输入、返回格式、凭据与授权范围。优先复用已连接工具；只有明确且重复的需求才封装脚本，不自动建立通用 API 平台、注册账号或付费购买。
4. 高成本生图、批量素材购买或长调研，先说明预计调用次数、范围及已知费用/时间；未知成本说明不确定性，等待用户批准再执行。已有明确授权覆盖该范围时不重复询问；有限、低成本的任务相关资源查找按现有授权推进。
5. 获取结果后检查实际文件或返回内容，再嵌入原型。生图适合角色、插画和纹理，交互控件、精确文字、价格及数据由 HTML/SVG/Canvas 排版，不把整个界面生成成不可操作的图片。

成本确认主要针对新增付费、批量生成/采购、预计需要多轮重绘，或超出本次原型范围的专项长调研。一次性本地绘制、已有授权素材复用和少量官方文档查找不额外审批；单次生图若收费或费用无法确认，也先说明并获取覆盖该调用的授权。遵守用户更严格的成本/时间约定，不能因为只调用一次就忽略费用。

外部失败不做无限重试。确认是缺权限、不可用或成本超范围时，说明具体缺口，提出能实现相近效果的方案；明显改变确认风格、布局、交付格式或质量时，先征求用户选择。明确要求三维或特定插画时，不能静默改成平面图并声称已达成。

## 资产清单与一致性

按需维护简短清单：`资源/库名称 → 来源 → 版本或生成方式 → 用途 → 许可/署名 → 打包方式`。使用实际来源，不编造授权；不确定能否再分发或内嵌时先核实，或者选可授权替代。

- 图标家族、描边粗细、圆角和光学大小一致；插画的色板、形状、人物与材质一致。
- 图像检查透明边缘、裁切、比例和分辨率；保留清晰度同时控制文件体积。
- 使用第三方库时按真实版本记录并保留许可证及要求的署名；字体、图片也单独核对使用范围。
- 付费授权、账号凭据及 API Key 不进入 HTML、资产说明或仓库。处理用户素材时遵守其授权，不为获取素材把无关个人数据发送给第三方。

## 离线单 HTML 的交付方式

制作可以联网获取资源或使用构建工具；最终文件按离线要求自包含：

- SVG 内联，图片按需转为 data URL，字体在许可允许时内嵌并按需子集化；保留必要的来源/署名。
- 库及其必需纹理、模型、字体或其他资源一并打包；不能只内嵌主脚本，留下动态 import、CDN 或远程素材请求。
- 模块型库按实际能力打包，检查 `file://` 下的跨域、本地 fetch 和加载限制，不假设网络教程代码复制后即可离线使用。
- 制作阶段获取的图片/模型等固化为本地内容，交付文件不包含生图或素材服务的实时调用和密钥。
- 用户明确接受联网预览时才保留必要外链，注明网络依赖与失败处理。若目标效果与单文件限制确实冲突，提出经过说明的替代交付供用户选择。

## 按效果验收

实际渲染后对照简报检查构图、文字层级、素材一致性、光影/材质、交互反馈和移动端可读性。复杂渲染重点检查交互是否流畅、重进页面是否重复创建场景、低性能/减少动效模式能否完成任务，以及导出是否完整。

离线交付须禁用网络后直接打开文件，走核心路径并检查需要的图片、字体、库与导出。只检测源码中没有 HTTP 链接，或只在开发服务器下成功运行，都不足以证明离线可用。没有对应工具时如实标明未验证。
