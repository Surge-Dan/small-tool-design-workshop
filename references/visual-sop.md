# 视觉制作与评审

用于高保真制作或重定视觉。以下是检查点，按任务合并或返回，不是固定页面、风格、多轮审批或额外文档。局部修改只处理受影响部分。

## 1. 把方向变成可见决定

沿用确认需求，先按[设计推导](design-engine.md)确定对象、动作与结构：先看什么、先做什么、结果怎么用。简约和复杂是表达方式，高保真是完成度。

实际查看少量参考，拆解比例、字形、素材、材质、密度与反馈。视觉依据与业务来源分开；参考不可访问时用已给素材或明确的原创方向，不编造看过的作品。

主要制作路线可组合，不是模板菜单或技术等级：

| 路线 | 精修对象 | 常见失效 |
| --- | --- | --- |
| `typographic`版式与字形 | 中文、数字、比例、对齐、阅读顺序 | 系统字加大片空白，没有具体层级 |
| `object-led`物件与材质 | 轮廓、厚度、光源、控件触感与状态 | 只有机身外壳，内容和操作无关系 |
| `asset-led`图片与构图 | 精度、裁切、色板、图文互让 | 粗糙占位图、混乱画风、素材遮挡操作 |
| `scene-led`空间与动态 | 对象关系、路径、层次、光影、生命周期 | 假3D、重进重复循环、动效遮挡 |

渐变、玻璃、奶油底、英文、卡片、粉色、粒子都可能适用。判断内容、情绪和整体表达，不用黑名单代替审美，也不要求所有装饰直接承担操作。

## 2. 先完成一个片段

方向不明时，用真实长度内容做关键画面；交互有实质取舍时补一段操作和结果。对照保持任务、内容、视口一致，差别超过换色；给推荐和代价，不实现多套完整产品。

先解决承担识别的资产与效果。人物、插画、艺术字、牌面和材质要确定获取/生成/绘制方式并查看实际文件，不静默替换为emoji或粗糙SVG。关键效果不确定时局部验证触控、字体加载、材质或导出。按[素材与渲染](visual-resources.md)选择方法。

确认方向、完整需求或明确委托不强加审批；内部验证仍做。只要小样就不推进完整业务。改变已确认效果、结构、交付约束才补选择，已有授权不重复问。

## 3. 从实际片段扩展规则

将字形、颜色角色、比例、网格、间距、图标重量、裁切、边缘、光源和状态写成实际参数，不套统一字号或间距。CSS字体名不证明真实字形加载，精修见[visual-language.md](visual-language.md)。

材质贯穿适用控件：按压、选中、不可用、错误和恢复有一致语义，不只画背景；不同区域的不同材质须有场景解释。

运动在结构阶段确定触发、对象、起止变化、结束动作、重复/中断与减少动效，按[动画与交互](motion-and-interaction.md)制作。结果不依赖动画结束。图像导出提前确定尺寸、裁切、透明度与渲染方式，实际查看文件，不假定DOM预览和导出天然一致。

用真实长标题、中文、极端数值、不同图片比例和密集结果扩展必要状态。说明按需展开，不靠长文案补偿难懂操作。

## 4. 分开检查，按原因修正

打开当前产物。默认检查390×844、320px及宽屏手机容器；其他设备按需求。离线须关闭缓存、禁用网络后首次直接打开文件并走核心路径；导出查看文件；动画观察前中后、重复、中断与减少动效。不能观察的范围标为未验证。

| 检查 | 依据 | 不能替代的东西 |
| --- | --- | --- |
| 视觉与独特性 | 同尺度画面、确认方向、参考迁移、实际资产与字形 | 自评分、库名、无报错 |
| 行为与结果 | 真实输入、状态变化、核心路径与恢复 | 按钮存在、静态样本、假等待 |
| 动态与连续性 | 实际运动、重复/返回、焦点与滚动 | transition声明、结束截图 |
| 显示与交付 | 容器、窄屏、首次离线加载、实际导出 | CSS声明、缓存、仅开发服务器成功 |

可用[design_review.py](../scripts/design_review.py)整理参考与当前画面，用[viewport_probe.js](../scripts/viewport_probe.js)读取实际边界，见[检查工具](review-tools.md)。工具不评价美丑、不代替操作或真机测试。

从用户、艺术指导、怀疑者和接手开发者的立场做有限复查：主操作可发现？画面符合方向？效果真实？哪些必须保留？默认当前Agent换立场，独立代理只在授权和环境允许时使用。

问题记录位置/状态、观察、类别、影响、处理和证据。先修核心阻断，再按原因处理：

| 原因 | 优先修正 |
| --- | --- |
| 主角或动作不明确 | 结构、信息顺序、就地操作 |
| 字形与比例失衡 | 实际字体、字级、单位基线、间距 |
| 资产粗糙或混乱 | 制作/替换资产、裁切、画风和构图 |
| 材质不成立 | 光源、边缘、厚度、控件状态 |
| 运动没有反馈 | 对象关系、路径、结束和中断 |
| 交付偏离 | 容器、加载、导出、恢复机制 |

不要把所有问题处理成换色加阴影。`blocker`修复后才称核心可用；`major`修复或有明确接受依据；`minor`按范围处理。偏好与违背确认方向分开。无具体问题时停止；有依据的修正仍不能收敛时展示差异，不无限微调。

## 5. 留下可继续实现的依据

同一份`visual.design_plan`记录对象、结构、参考迁移、保留特征、渲染；`visual.review`记录对照依据、级别、发现与处理。单HTML可用简短内部记录，跨会话或交接才维护JSON。证据绑定实际观察版本，不重标哈希冒充复测，见[iteration-and-evidence.md](iteration-and-evidence.md)。

交付当前原型、已实现操作、设计依据和验证范围。按需导出开发包，不编造Figma源文件；打包不证明好看，主视觉未完成不能推给生产阶段。与普通Agent比较需同条件产物和用户反馈，见[内部对照](../evals/comparison.md)。
